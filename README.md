# medbox-mobile

A family medicine box that lives entirely on one phone.

Track what's in the box, when each container expires, when it's time to
restock, and let a daily ledger draw down the medicines someone takes every
day. No account, no sign-in, no cloud, no sync — one SQLite file on one
device.

The app is the successor to a small web app, and the two share a data format:
it imports and exports the same `all.json` (`version: 1`), compatible in both
directions. That file is the permanent escape hatch — the data is never locked
inside the app.

The interface is in Chinese.

## What it does

- **Import** — read an existing `all.json` exported from the web version.
- **Expiry tracking** — a container can carry a printed expiry and, once
  opened, a "days after opening" window. The effective date is whichever
  comes first.
- **Restock forecasting** — days of supply per medicine against a threshold
  you set.
- **Auto-deduction** — for medicines taken daily at a fixed dose, the ledger is
  drawn down on each cold start and each return to foreground. Every change is
  an append-only event: corrections are new events, never edits to history.
- **Local notifications** — a single summary at 9:00 on days when something
  needs attention. It deliberately contains no medicine names.
- **Export** — regenerate `all.json`, or share a plain-text in-stock list,
  through the system share sheet.

## What it deliberately doesn't do

Accounts, login, cloud sync, multi-device, barcode scanning, medical advice,
medication check-off, multiple boxes.

## Stack

Expo (React Native) + TypeScript + `expo-sqlite` + Drizzle ORM.

There are exactly two native dependencies, each forced by a requirement rather
than convenience:

| Dependency | Why there's no way around it |
|---|---|
| `expo-sharing` | The only way to raise the system share sheet. No pure-JS substitute. |
| `expo-notifications` | The only way to reach the user without the app running. A JS timer can't: JS only runs while the process is alive, and the whole point of a reminder is to speak when the user isn't thinking about the app. |

Write-ahead logging is explicitly disabled, so that "a backup is one file"
actually holds.

## Testing

415 tests across 17 suites (`npx jest`), in three groups:

- the domain rules, translated case by case from the upstream requirements;
- the storage layer, exercised against a real SQLite;
- **structural guards** that read the source, strip comments and assert
  architecture — gate ordering, which module may import what, which fallback
  values are allowed where.

The third group exists because those constraints have no runtime symptom. They
break silently and surface months later on a real device.

The fixture under `test/fixtures/` is not a synthetic sample: it is a real
family's medicine list, kept because the acceptance criteria and the golden
numbers were established against it.

## Building

Requires Node, a JDK, and the Android SDK. The native `android/` directory is
generated, not committed:

```bash
npm install
npx expo prebuild --platform android
bash scripts/android-signing.sh      # needs your own keystore, see below
./android/gradlew -p android assembleRelease
```

`android/` is deleted and regenerated by every `prebuild`, so signing config
and `local.properties` have to be re-applied each time — that is what
`scripts/android-signing.sh` does, idempotently.

Release signing expects a keystore at `keys/medbox-release.keystore` and its
passwords in `keys/keystore.properties`. **Neither is committed.** Generate
your own — the script prints the `keytool` command if the keystore is missing.
Android requires an upgrade to be signed with the same key as the installed
build, so once an app is on a device, replacing the key means uninstalling it
first. This app keeps everything in one local database, so uninstalling loses
the data.
